# D10 : passage Monbezon réel, livraison WIP séparée

D9 reste figé. D10 sert un seul passage historique et sa révision r1 exacte, sans changer le contexte D3 : lecture `unreviewed`, droits publics `pending`, traduction/acte/document null, association d'objets seulement. `delivery-mandate.json` enregistre séparément le mandat humain de diffusion des travaux en cours et de réception des propositions. Ce mandat ne vaut ni approbation des droits ni validation historique. Ce candidat est préparé, pas déployé.

Entrée Node/Vercel : `function.mjs`, `(request, response)`. Importer le module ne lit pas l'environnement et ne crée pas de pool. La première requête configurée charge le bundle exact ; six valeurs requises manquantes ou un bundle altéré refusent avant pool. Le pilote requiert le profil `monbezon-wip`, l'origine `https://valerianteissier.com`, un nouveau schéma `archive_corrections_d5_public_wip` avec suffixe facultatif court, une URL PostgreSQL sans options, une clé HMAC privée et le mode propriétaire `disabled`. Les noms figurent dans `env.example`, sans valeur.

Routes : `GET /api/archive/public/monbezon/health`, `GET /api/archive/public/monbezon/passage?passage_id=text%3Aatelier-494756c2009be577ad11a5eb0a662d38`, `POST /api/archive/public/monbezon/corrections`. POST accepte exactement `passage_id`, `base_revision`, `replacement_text`, `reason`, `evidence_refs`, `simulation:true`, plus `Idempotency-Key` et l'Origin exact. Les propositions restent anonymes et séparées du texte source. Les sept routes auth/propriétaire refusent 403 avant SQL, sans cookie ni décision. `simulation:true` est le contrat technique hérité ; `data_kind:historical-local` identifie le vrai texte, jamais une fixture rebaptisée.

Seeding opérateur explicite, à exécuter **ultérieurement** après configuration approuvée d'un PostgreSQL et d'un rôle opérateur distinct : `node scripts/archive-corrections/public-wip/seed.mjs --seed-new-schema <prepared-bundle-directory>`. Le script exige un schéma absent, applique les migrations D5 inchangées, insère le contexte/r1 exact et vérifie leurs empreintes. Il ne crée aucun propriétaire, mot de passe ni session. Il refuse les schémas existants. Les privilèges runtime préparés dans `runtime-grants.sql` permettent seulement les écritures de propositions/requêtes/rate limits ; les décisions/révisions et tables propriétaire ne sont pas inscriptibles.

Pour le montage local de Root, charger le bundle préparé via `loadDeliveryBundle(directory)`, seeder une base locale neuve explicitement possédée via `seedExactContext(driver,{schema,...bundle})`, puis appeler `createLocalWip({driver,schema,...bundle,origin:'http://127.0.0.1:<port>',sessionKey})`. La fabrique retourne `{handler,close}` et ne crée/seede pas de base automatiquement. Aucune variable de production n'est nécessaire. Ne pas ouvrir/réutiliser D8. Root gère son propre serveur, son port, son stockage neuf et sa fermeture.

Dans le nouveau package seulement, copier les fichiers de `runtime-allowlist.json` à leurs destinations relatives. Les modules, migrations, deux JSON exacts et wrappers `api/` restent hors du dossier statique. Utiliser D10 pour les wrappers Monbezon, D9 uniquement pour sa fixture si elle est conservée ; leurs wrappers Monbezon occupent les mêmes destinations et doivent être sélectionnés explicitement, pas écrasés dans les sources fermées. Fusionner seulement `vercel.additions-only.json` en préservant build/output, en-têtes et GET de Root. La règle doit inclure les deux migrations et les JSON de livraison. Node 24.x, `pg@8.23.1`, `@vercel/functions@3.9.11` et le package/lock D5 existants sont inchangés ; une future construction autorisée doit provisionner ces dépendances. Aucun installCommand, installation ou déploiement ici.

Le gate utilise seulement des requêtes/réponses en mémoire et une nouvelle base PGlite privée. Sa proposition technique reprend r1 sans changer un mot ; aucune correction historique n'est inventée. Le succès prouve le raccord et la persistance locale, pas un hébergement ou PostgreSQL externe. Données, sources et preuves fermées sont vérifiées par empreinte ; aucun original, secret, réseau ou store D8 n'est lu.
